# Insane error management

## Why is it shit?
At least I tried to manage the errors, but with this type of management,
it would have been better to do nothing. So, for context... for some commands in my CLI,
I used Node.js's file system (`fs`) module. At the time, I didn't really understand 
the difference between promises and why older methods used callbacks. So, how did 
I manage errors like a "professional"? Behold:
```js
fs.readFile("file.txt", "utf-8", error => {
    if (error) console.log(error)
})
```

## How to stop being shit
Logging an error to the console is not "error management", it's just watching your program crash in 4K. If the file fails to read, the rest of the CLI will keep running with undefined data and break anyway. 

To fix this, modern Node.js gives us `fs/promises`, allowing us to use `try/catch` blocks with `async/await`. If you are stuck using callbacks, at least throw the error (`throw error`) or return early to halt execution. Don't just print the error and pray for the TC39. Handle it so your app can fail gracefully or retry the operation.
