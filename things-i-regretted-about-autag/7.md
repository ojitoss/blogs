# Version controlling

## Why is it shit?
I released around 22 versions, reaching v3.2.2 in no time. This only happened because I made so many mistakes and kept pushing hotfixes within minutes of each other. Pretty much all of these 22 versions were made in a span of about 3 months or even less (or maybe more, I might just have a bad memory). 

Instead of properly testing my code locally, I was essentially using the npm registry as my personal development environment, deploying a new version every time I fixed a tiny typo.

## How to stop being shit
Before building a serious project (or at last try it), learn what **SemVer (Semantic Versioning)** actually is and how to use it properly. Avoid spamming the registry with endless micro-updates; it's much better to release one solid, well-tested update per month than 4 broken updates in a single week.

To achieve this, stop rushing to hit `npm publish`. Test your packages locally first using commands like `npm link` or `yalc`. Make sure everything works in a clean environment before changing your version numbers. Versioning is a communication tool for your users, not a save button for your code.
