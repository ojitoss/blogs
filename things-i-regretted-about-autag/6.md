# This breaks the project

## Why is it shit?
Just one single dependency broke the entire project. For some reason, in a tool designed exclusively to create and edit files or folders, I decided to add an option to translate text using a Google Translate API package. Yes, it makes absolutely no sense for this feature to exist in this type of project. But to make things worse, this choice makes the CLI completely **unusable** today because that specific package was deleted from npm.

## How to stop being shit
Don't add features that don't matter. It’s just stupid bloatware and it makes no sense, especially in open-source projects. You don't need to bloat your app with random features that no one asked for just to make your project look "bigger." 

More code and more dependencies just make your project unsafe and fragile. This is a classic example of **Dependency Hell** and supply chain vulnerability. To stop being shit, follow the **Single Responsibility Principle**: make your tool do one thing, and make it do it perfectly. If your CLI is a boilerplate generator, it doesn't need to translate text, fetch the weather. Fewer dependencies mean fewer things that can break your project 4 years down the road.
