# Over-engineering

## Why is it shit?
My project had like 13 commands. They were simple commands, so the best option would 
have been to just make one file per command. So, I did exactly that when I was working 
on this shit, right? Well... no. I decided to make something "professional and clean": 
one folder per command, a ```normal.js``` file to handle the command logic, and a ```global.js``` 
file that exports the handler.
```txt
|__ functions/
|_____ command/
|________ global.js
|________ normal.js
```

To achieve peak professionalism, I used an ultra-necessary class (with the 
```global_object``` thing, of course). Here is an example of one of the masterpieces I created:
```js
const { normalRemove } = require('./normal.js')

let global_object = new Object();
class removeManager {
    constructor(){}

    normal(){
        normalRemove();
    }
}

module.exports = removeManager;
```

An empty constructor and a method that literally just calls another function. Definitely a perfectly 
implemented class. 

But it doesn't end here. To make it even "cleaner," I had an ```export.js``` file 
that exported all methods into a single object:
```js
module.exports = {
    initManager: require('./functions/init/global.js'),
    fileManager: require('./functions/file/global.js'),
    ignoreManager: require('./functions/ignore/global.js'),
    licenseManager: require('./functions/license/global.js'),
    mkdirManager: require('./functions/mkdir/global.js'),
    translateManager: require('./functions/translate/global.js'),
    renameManager: require('./functions/rename/global.js'),
    removeManager: require('./functions/remove/global.js'),
    readManger: require('./functions/read/global.js'),
    localManager: require('./functions/local/global.js'),
    renderManager: require('./functions/render/global.js'),
    copyManager: require('./functions/copy/global.js'),
    minifyManager: require('./functions/minify/global.js'),
    searchManager: require('./functions/search/global.js')
 }
```

Yep, it still doesn't end. Look at how I initialized everything in the main file:
```js
const fs = require('fs');
const { initNormal } = require('./functions/init/normal.js');
if (!fs.existsSync('.autag')) initNormal();
const autag = require('./export.js');
const file = new autag.fileManager();
const ignore = new autag.ignoreManager();
const license = new autag.licenseManager();
const mkdir = new autag.mkdirManager();
const translate = new autag.translateManager();
const rename = new autag.renameManager();
const remove = new autag.removeManager();
const read = new autag.readManger();
const local = new autag.localManager();
const render = new autag.renderManager();
const copy = new autag.copyManager();
const minify = new autag.minifyManager();
const search = new autag.searchManager();
const inquirer = require('inquirer');
```

## How to stop being shit
More code does not mean better code. I created a labyrinth of folders, wrappers, and classes just to run 13 basic functions. I fell into the trap of thinking that abstraction automatically makes you a senior developer.
To fix this, embrace the **KISS principle (Keep It Simple, Stupid)**. If a command is just a function, export the function. You don't need a manager, a factory, or an empty class just to pass a callback. Write your code as simply as possible first, and only abstract or create architecture when the project's growth actually demands it. Otherwise, you're just writing boilerplate to feel smart.
